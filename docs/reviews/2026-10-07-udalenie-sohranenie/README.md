## Обязательная серверная зависимость — Claude
На проверенном getfit-sync 4f8ae57 /meal/del удаляет без снимка и возвращает today; /meal/restore отсутствует. **Самостоятельно этот клиент не выпускать.**

POST /meal/del {uid,id,operation} → {ok:true,day} исходного дня, сохраняет полный серверный снимок строки, включая фото, состав, время, дату, id, src, приватность и остальные поля без пересчёта. POST /meal/restore {uid,id,operation} → {ok:true,day} исходного дня. Исходные данные не передаются клиентом. Повторы одной операции идемпотентны; проверка владельца; более свежую существующую запись не перетирать. Restore должен отменять поздний delete той же operation при потерянном ответе/гонке. Срок жизни снимка не 5 секунд, а минимум 10 минут на задержки и ручной повтор. Обработка фото/GC должна сохранить возможность точного возврата. Требуются серверные контрактные тесты, включая чужого uid, полный снимок, двойной restore, restore до завершения delete. Mock подтверждает клиент, не наличие этой реализации на сервере. Контракт заранее передан в status/codex.md.
