## B: пакет решений, без самовольной реализации

1. **B1 — случайное удаление.** Приём и упражнение удаляются иначе, чем день зала и сброс профиля. Предлагаю для приёма/упражнения отменяемое удаление с «Вернуть», для массового удаления — подтверждение. Альтернатива — подтверждение каждого удаления. Требуется решение, поскольку это меняет действие кнопок.
2. **B2 — порядок упражнений.** Добавить видимую кнопку «Порядок» рядом с добавлением, оставив долгое удержание; либо оставить только жест. Скрытый жест не мёртвый, но новичок его не обнаружит по экрану.
3. **B3 — picker упражнений.** Сейчас «Все», 20+ чипов мышц, «899 / показано 80», нет «ещё» в листе выбора (на странице каталога есть). Предлагаю короткие группы с поиском и дозагрузкой; альтернатива — оставить нынешний поиск с длинным набором фильтров. Нельзя молча ранжировать упражнения медицинской «полезностью».
4. **B4 — слова и плотность.** «Белок» в Теле — расчётная масса, в Еде — граммы питания; «Срез» понятен не всем. Предлагаю «Белок тела» / «Изменения тела» и оставить подробности внутри раскрытий. В меню недели — выбор дня вместо длинного повторения семи меню. Переименование и новый порядок просмотра согласовать; расчёты и серверные тексты не переписывать.
5. **B5 — талия отдельно.** Разрешать ли запись только талии без сегодняшнего веса? Сейчас форма общая, но не объясняет обязательность веса. A5 исправляет молчание, не добавляет такую запись.
6. **B6 — сохранение форм.** В профиле/расписании изменения действуют сразу, у приёма — только после «Сохранить». Рекомендую сохранить эти способы, явно показывать «Сохранено» у автосохранения и предупреждать о незаписанной правке приёма при закрытии. Альтернатива — явное «Сохранить» везде; это большее изменение, не делать одним косметическим патчем.
7. **B7 — неделя еды как навигация.** Сделать строку даты кликабельной с открытием этого дня, как дни недели на главной? Сейчас строка — только график; ошибки обработчика нет, обработчика намеренно нет.

Не выношу повторно уже решённое: одинаковый вид завершённых тренировок; круговая программа; три основных приёма; свободный день без просьб записывать еду; отсутствие подтверждений планового спорта; Срез по ссылке из бота; таймер отдыха по желанию; степень тонкости контуров карты тела.

## Проверки и границы вывода

- **180 состояний экранов и листов**: 45 × две ширины × две темы; в финальном `inventory.json` нет исключений сценария открытия, необработанных JS-исключений и горизонтальных вылетов по измерению DOM. Это проверка стендовых состояний, не гарантия всех устройств. Четыре HTTP 503 относятся к намеренному отказу реакции. Наличие `.show` не равно верхнему доступному листу: визуальная проверка и hit-test выявили A9, несмотря на техническое прохождение открытия.
- **36 адресных воспроизведений**: девять сценариев × четыре сочетания; A1–A7 и A9–A10 подтверждены, вход в подписку через чат — положительный контроль. Они специально показывают неправильный результат старого кода, а не «зелёные тесты исправлений».
- **38 наборов действий × четыре сочетания = 152 запуска.** 150 прошли неизменными. Два `mnenie` на 320 нажимают ниже окна: ручка третьей группы начинается на y≈976 при высоте 900. Повтор той же проверки с прокруткой перед захватом (`prohod-order.js`, обе темы) прошёл, включая перенос и сохранение порядка. Исходные два красных лога сохранены, не выданы за ошибки продукта.
- Первые ошибки адаптера матрицы были отделены от приложения: копия options не возвращала тесту накопленные mock-поля; блокировка картинок мешала проверкам изображений. Адаптер исправлен, затронутые сценарии повторены. Утверждения исходных `test-*.js` не менялись.
- Первый полный `sh tg/run.sh --все`: **92/93**, 221,4 с; `test-minuty` упал на «до ответа тренировка не сохранена». Отдельный повтор: **1/1**, 16 с. Это нестабильность/гонка между автосохранением и сценарием подтверждения, которую нельзя объявить исправленной этим аудитом. Надо проверять отсутствие финализации/неподтверждённого dur, отдельно от допустимого чернового автосохранения (`commit` ставит отложенную запись). Повтор полного прогона записан ниже.
- Проверки контраста `test-ds1`, viewport, листов и safe-area в полном прогоне прошли. Визуально просмотрены обе темы и узкие состояния дуги, карточки упражнения/таймера, меню, профиля, Среза, picker и знакомства. Фотографии и отзывы реальных людей не использовались.

Повторный полный `sh tg/run.sh --все -j 6`: **93/93, 492,3 с**, включая `test-minuty`. Первый красный результат не скрыт; он остаётся свидетельством чувствительности проверки к нагрузке, а не исправленного нами кода.

## Как делить исправления без конфликтов

1. **Сначала Claude заканчивает зал прошлой даты.** Его область — дата сессии, ключи, журнал, очистка, finish, list/day headers. Дополнительные проверки: повторное исправление вчера, очистка вчера не стирает сегодня, маршрут из дуги, история подходов; не считать прошлый зелёный прогон проверкой нового HEAD.
2. **После его интеграции Codex берёт A1–A3 + A6 одним блоком «Дата и отправка».** `loadDay/loadDayScore`, контекст добавления еды, `openCoach/cGo/coachSend`. Эти функции связаны, разбивать их между двумя одновременными правками index.html не надо. Серверный контракт даты проверяет Claude отдельно. При A3 без автоматической повторной отправки.
3. **Следующим отдельным коммитом Codex A4–A5 + A8 «Замеры и подсказки».** Только обработчики формы на главной, локальный статус и пустой Журнал. После приёмки предыдущего блока.
4. **Затем Codex A7 + A9–A10 «Отправка и доступный лист подписки».** Claude проверяет контракт `/menu/send` и пути входа в подписку; не менять генерацию/планирование меню. Если предпочтительнее параллельность, Claude может писать серверные контрактные тесты, пока Codex работает в index.html.
5. **B — после ответов отдельными небольшими этапами.** Нельзя смешать исправление неправильной даты с новой навигацией недель или перестройкой профиля: иначе трудно проверить, что починили.
6. Перед каждым выпуском: новые проверки должны падать на `90935f0`, проходить на исправленном коде; обязательный полный прогон, контраст/viewport двух тем, снимки затронутых состояний, независимое ревью. Выпуск только Claude после «да» Шохруха. Этот отчёт ничего не выпускает и не начинает этап 0.
